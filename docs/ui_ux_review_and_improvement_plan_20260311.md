# UI/UX 見直しメモと改善計画

更新日: 2026-03-11  
目的: 低 IT スキルの現場担当者でも、1 度教えれば迷わず使える画面構成に近づける

---

## 1. 見直しの基準

今回の見直しでは、次を基準に評価する。

- 次に押すボタンが一目で分かるか
- 何かを確認したいとき、どの画面を見ればよいかすぐ分かるか
- 専門用語なしでも理解できるか
- 普段使わない設定や詳細情報が最初から見えすぎていないか
- 1 回教えれば、その後は自力で回せるか

想定ユーザー:

- 中小企業の現場担当者
- PC や Web システムに慣れていない
- コード、ID、API、JSON のような用語は前提にしない

---

## 2. 見直しで見えた問題

### 2-1. 文書の問題

- 既存の操作マニュアルに古い受付方法の説明が残っていた
- 現在の 3 行ナビ構成と古い説明が一致していなかった
- `ユーザー1` と `ユーザー2` の役割が混ざっていて、自分が見るべき画面が分かりにくかった

### 2-2. 画面の問題

- `注文書アップロード` に、通常不要な項目が最初から見えていた
- `注文一覧` が、検索や進捗情報より「まず何をすればいいか」の説明が弱かった
- `日別出力` が、何のための画面かを知らないと意味が分かりにくかった
- ダッシュボードに役割別の導線がなく、最初の一歩が分かりにくかった

## 4. 実装方針

今回は、既存の OCR や注文ロジックを変えないことを優先した。

- OCR ロジック: 変更しない
- 注文生成ロジック: 変更しない
- API の意味: 変えない
- 変えるのは、表示文言と導線、初期表示の情報量だけ

---

## 5. テスト方針

### 5-1. 回帰を避けるための確認

- frontend typecheck
- 既存 OCR 回帰テスト
- 既存 order / sheet / bag 周りの回帰テスト

### 5-2. 目視で確認すること

- `注文書アップロード`
  - PDFだけで登録できるか
  - 補助入力が折りたたまれているか
  - 登録後に次の行動が分かるか
- `注文一覧`
  - まず何を見ればいいかが分かるか
- `日別出力`
  - この画面の用途が読んで分かるか
- `ダッシュボード`
  - ユーザー1 / ユーザー2 の入り口が分かるか

---

## 6. まだ残る課題

- `注文詳細` は依然として情報量が多い
- `施設一覧` は上級者向けの情報がまだ多い
- `日別出力` は便利だが、初心者には情報量が多い
- `注文一覧` は進捗一覧と注文一覧が同じ画面にあり、将来的には分けた方がよい

---

## 7. 次の候補

今回より先の改善候補:

- `注文詳細` の debug / 上級機能をさらに折りたたむ
- `施設一覧` に通常モード / 管理者モードを分ける
- `日別出力` に用途別タブを入れる
- `注文書アップロード` 完了後に、対象注文へ自動で行きやすくする

---

## 8. 判定

今回の改善で、次はかなり見えやすくなった。

- ユーザー1:
  - どこから始めるか分かる
- ユーザー2:
  - PDF をどう登録するか分かる
- 発注者:
  - 何を確認してもらえばよいか分かる

ただし、`注文詳細` はまだ 1 回の説明が必要な重さがある。  
よって、今回の改善は `本番前の最低限の整理としては妥当`、`完全に初心者だけで迷わず回せるところまでは未達` と評価する。
