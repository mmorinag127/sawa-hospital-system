# CI review and parallel split — 2026-10-21

Scope: hospital repository CI at base `81b1aa2`. School/MCP functional changes and deployment workflows are not modified.

## Approved changes

- Run existing US1–4, saved-source and OCR regression commands in three isolated matrix jobs.
- Keep job ID `backend` because the PostgreSQL fixture checks `GITHUB_JOB`.
- Keep the visible `backend` check through an `always()` aggregate that requires matrix result `success`. Failure, cancellation and skipped results must not pass.
- Keep all pytest targets/options, dependencies, environment and PostgreSQL fixture checks. Disable matrix fail-fast so other suites still provide evidence.
- Cancel superseded CI runs only for the same pull request. Push runs retain unique groups; deployments are outside this workflow/group.
- Use suite-specific log artifacts to avoid upload name collisions.

## Findings

1. **Serial critical path:** the three independent invocations add together. This change parallelizes them without deleting tests. Actual speed must be measured on Actions; an estimated lower critical path is not a verified result.
2. **Repeated database setup:** `owned`/`owned_pg` are function-scoped and create/migrate databases repeatedly. `test_delivery_admission_hardening` consumed 264 seconds across 602 cases. Migration/isolation checks are legitimate; do not replace them with shared mutable DB state merely for speed. Setup-vs-call profiling is needed before changing fixtures.
3. **Heavy real component paths:** canonical saved projection consumed 127 seconds across 15 cases, including raster/checkpoint/materialization work. These are not ordinary cheap unit tests. Mocking those paths away would weaken the checks.
4. **Manual backend selection:** default CI lists 81 test files; the tree contains 402 `test_*.py` files. This is not a coverage percentage: helper imports, standalone/manual workflows and obsolete tests require classification. New tests can miss default CI unless added deliberately.
5. **UI/build scope:** default CI runs component/config tests and typechecking, not `test:e2e` or a production Next build. Build/runtime and live acceptance checks exist in separate deployment/manual workflows. A green default CI alone does not prove the deployed operator flow.
6. **Coarse trigger and duplicate work:** any non-documentation PR runs all groups. No path filtering is added here because dependency-safe selection has not been established. Superseded same-PR runs were also overlapping; that is addressed by the approved cancellation rule.
7. **Mutable dependency install:** Python editable dev install plus pip upgrade/audit happens in every job; pip caching exists. Install cost was small relative to tests. Matrix splitting repeats setup work and may increase total runner-minutes while reducing elapsed wait.
8. **Branch gate:** the branch protection required-status-check API returned `Branch not protected` for develop. This does not inspect all possible repository rulesets. No repository access policy is changed. Existing workflow check names are preserved.
