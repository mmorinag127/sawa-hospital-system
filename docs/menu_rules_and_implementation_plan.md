# 月次メニュー ルール整理と実装計画

## 目的
- 週次メニューマスターを月次メニューマスターに移行する。
- 基本ルール＋メニュー例外＋施設例外の3層ルールで袋分け数量を決定できるようにする。
- ルールの運用負荷を下げ、将来の拡張（食種追加/例外増加）に備える。

## 入力ファイルの前提（input_example/献立表　12月.xlsm）
- シート名: 「掲示用（料理・食品）」のみ。
- ヘッダ: 「献立種類：常食(通常)」「年月日：YYYY年MM月DD日～YYYY年MM月DD日」。
- 曜日行: 1回だけ（行7付近に「日/月/火/水/木/金/土」）。
- 日付列: 7列（B/J/R/Z/AH/AP/AX）で1週間分、以降週ごとに同列構造が繰り返し。
- ブロック構造:
  - 朝食: ラベル行 + 2行
  - 昼食/夕食: ラベル行 + 3行
  - 栄養行（エネルギー/脂質/食塩）は除外対象
- 0/空セルは除外対象。

## ルール整理（運用ルール）
### 基本量（global）
- 朝食: メイン70g x1 + 副菜40g x1
- 昼食/夕食: メイン100g x1 + 副菜40g x2

### 料理別の例外（menu）
- カレー:
  - メイン140g + 副菜40g + 漬物5g or フルーツ40g
- 添え表記（例: “添)” を含むメニュー）:
  - 添えは基本30g
- ハンバーグ/魚の塩焼き:
  - メイン量が小さいため、副菜を50g/60gに増量する場合あり
  - 副菜量の実態: 40g / 50g / 60g が存在

### カロリー別（1600kcal）
- 1600kcalは昼夕のメイン量を増量
  - 鶏: 100g → 140g（添えなし）
  - 豚: 100g → 130g（添えなし）
  - 魚: 2切 → 3切（添えあり、添え量は同じ）
  - ハンバーグ: 60g → 80g（表示は1個のまま）
- 1600kcalは「180g固定」の制約を持たない
- 副菜60gになるケースもあり

### 食種
- 常食 / 軟菜食（各: 普通量 / 1600kcal）
- ミキサー食は軟菜食と同一メニュー
- 施設によっては軟菜食が発注書に出てこない（別資料参照が必要）

### ルール優先順位
1. 施設＋メニュー例外
2. 施設例外
3. メニュー例外
4. 基本量（global）

## 実装計画
### 1) データモデル
- 月次メニュー: `monthly_menus` / `monthly_menu_items` を新設
  - id: `YYYY-MM`
  - filename, month_start などを保持
- ルール管理: 3層ルールをテーブル化
  - `menu_rules_global`
  - `menu_rules_by_menu`
  - `menu_rules_by_facility`
- ルールには `priority` と `scope`（朝/昼/夕、食種、カロリー区分）を持たせる。

### 2) 月次メニューのパーサ
- `menu_service` に月次専用パーサを追加
  - `pandas.read_excel(..., header=None)` で生データ取得
  - 曜日行・日付行の検出 → 年月補完 → 朝/昼/夕ブロック抽出
  - 「エネルギー/脂質/食塩」行は除外
  - 月内のメニュー名ユニーク集合を保存
  - 将来向けに「日付×時間帯×メニュー」も保持可能にする

### 3) API/画面
- `/weekly-menus` を `/monthly-menus` に置き換え
- 画面表記を「週次」→「月次」に変更
- 月次メニュー編集画面は現行UIを踏襲
- ルール管理画面を新設
  - global: 朝/昼/夕 × 食種 × カロリーの基本量
  - menu例外: メニュー名ルール（完全一致/部分一致/正規表現）
  - facility例外: 施設選択＋メニュー名＋上書き値

### 4) ルール適用ロジック
- OCR結果 → メニュー名 → ルール適用で数量決定
- 適用順序は「施設+メニュー > 施設 > メニュー > global」
- 複数一致時は `priority` で解決

### 5) 移行と検証
- 旧 `weekly_menus` は移行中は維持（互換期間）
- 既存OCR注文の表示に影響が出ないように段階切替
- 単体テスト: パーサ / ルール優先順位 / 例外適用
