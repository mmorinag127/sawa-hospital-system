# 独自ドメイン・DNS・Google設定の確認依頼テンプレート

対象: 発注者 / 取引先担当者 / 情報システム担当  
用途: 独自ドメインと Google ログインの本番設定に必要な情報を、専門用語を減らして確認する

---

## 1. 先に伝えること

今回のシステムは、次の形で本番運用したいと考えています。

- ログインは Google アカウントで行う
- 注文書はメール自動取込ではなく、PDF を画面から直接アップロードする
- 本番用の URL は、会社の独自ドメイン配下にしたい
  - 例: `app.example.co.jp`

そのため、ドメインと Google の設定に必要な情報を確認したい、という前提で依頼します。

---

## 3. 用語の説明

### 独自ドメイン

会社が使っているインターネット上の住所です。  
例: `example.co.jp`

### DNS

そのドメインを「どこにつなぐか」を決める設定です。  
今回だと、「`app.example.co.jp` に来たらこのシステムへつなぐ」という設定を入れます。

### Search Console

Google に対して「このドメインは自社のものです」と証明するための仕組みです。  
Google ログインの本番設定で使います。

---

## 4. こちらが受け取れれば次に進める情報

最低限、次の 3 つがあれば前に進めます。

- 会社のドメイン名
- DNS を触れる担当者
- Google 設定に使う管理アカウント

ここまで分かれば、次は「どの DNS レコードを追加してほしいか」をこちらで具体的に書けます。

---

## 5. こちらが次に返す内容

発注者から情報をもらったあと、こちらは次を返す想定です。

- 本番 URL 案
  - 例: `app.example.co.jp`
- 開発 URL 案
  - 例: `dev-app.example.co.jp`
- DNS 設定内容
  - 何を追加するか
  - どの値を入れるか
- Google 側で設定する内容
  - ホームページ URL
  - プライバシーポリシー URL
  - 利用規約 URL
  - Authorized domain

---

## 6. 今回の構成

- Google ログインは残す
- メール自動取込は使わない
- PDF を画面から直接アップロードする
- 本番 URL は独自ドメインにする

この形にすると、メール監視や認証トークン失効に引きずられず、運用がかなり単純になります。
