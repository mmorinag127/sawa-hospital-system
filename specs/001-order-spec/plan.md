## Summary

Fax/PDF添付メールを即時取り込み、施設×週の注文を生成し「要確認」で一覧化する。運用者はPDFビューアを見ながらインライン修正し「確定」でラベルCSV・納品書Excel・製造総量CSVを自動更新する。週次メニュー設定と施設マスター（抽出定義/袋分け/ラベル/納品書）で施設差分をコードレス吸収し、重複週PDFは新しいものを優先、未処理メールはダウンタイム後に追いつかせる。

**Language/Version**: Python 3.11  
**Primary Dependencies**: FastAPI, Pydantic, SQLAlchemy, Celery (async ingest/exports), pdfplumber + Tesseract OCR, pandas for CSV/Excel generation, Playwright (UI e2e)

**Target Platform**: Linux server, PCブラウザ（管理/運用）

**Performance Goals**: 95%のPDFを受信→要確認2分以内、確定→出力2分以内、バックログ(100施設/日)を30分以内で解消  
**Constraints**: 即時処理(JST)、マスター駆動の施設差分、PC限定UI、確定ワンアクション保存、重複週PDFは最新版のみ採用  
**Scale/Scope**: 100施設/日、週次メニュー1週分、施設マスター拡張で新施設追加

## Execution Plan (Ordered)

1. **Environment & Infrastructure**
   - Provision PostgreSQL, Redis, and S3-compatible storage or filesystem paths.
   - Install Tesseract (Japanese) and pdfplumber dependencies; set TESSDATA_PREFIX.
   - Configure retention window (1–2 months) and timezone (JST) for services.
   - Wire mail ingress to ingestion endpoint/service (accept PDF URI + metadata).
2. **Backend Foundations**
   - Scaffold FastAPI project with Celery workers (ingest/export) and structured logging with FAC/WEK IDs.
   - Define models (Facility, FacilityArea, FacilityMasterConfig, WeeklyMenu, MenuItem, OrderDocument, Order, OrderLine, Bag, LabelRow, DeliveryNote, ManufacturingAggregateRow, User, AuditLog, Notification) per data-model.md.
   - Implement RBAC/auth: admin via Google OAuth, operator via ID/PW (session/basic), enforce roles on routes.
3. **Ingestion & Facility Resolution**
   - Implement email ingest endpoint → queue job; store PDF, create OrderDocument + initial Order (未着/要確認).
   - Implement OCR/extraction pipeline with retries, facility region extraction; mark facility unresolved when low confidence; support manual selection.
   - Enforce duplicate facility-week handling (latest supersedes, old excluded from outputs).
4. **Operator UX (PCのみ)**
   - Build UI pages: order list with statuses/filters, PDF viewer, inline line editing, facility selection when unresolved.
   - Ensure single “確定” action commits edits; status vocabulary limited to 未着/要確認/確定/エラー.
5. **Confirmation & Outputs**
   - Implement confirm endpoint to lock corrections and trigger regeneration of label CSV (CP932), delivery note Excel, manufacturing aggregate CSV.
   - Apply change-column precedence, zero suppression, cold/hot/expiry rules from facility master.
6. **Master Data & Menu Management**
   - Admin UI/APIs for facility master configs (templates, packaging rules, label profiles, invoice mappings); validation tooling; import/seed scripts.
   - Weekly menu upload + per-line edits (unit, qty, temp, daypart, category); facility overrides via replacement.
7. **Observability, Audit, Reliability**
   - Structured logging, audit logs for uploads/edits/config changes/confirmations; notification routing (business vs system errors).
   - Backlog/health endpoint; requeue/idempotency for ingest/exports; scheduled backlog catch-up after downtime.
8. **Testing & Performance**
   - Contract/integration tests: ingest→facility解決→menu mapping→outputs; OCR retry/duplicate replacement/zero suppression/change-column precedence/backlog recovery.
   - Playwright e2e (未着→要確認→確定 with PDF viewer + inline edits).
   - Golden-file tests for label CSV/Excel outputs; load/performance checks for 95% ≤2min ingest/output and 30min backlog catch-up @100施設/日.
9. **Hardening & Release**
   - Security review (authz, data retention, encryption in transit/at rest), UX compliance check (PC-only, single confirm).
   - Deploy to staging; run full test suite; validate monitoring/alerts; prepare rollback plan.
