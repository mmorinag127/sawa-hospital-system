## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添付PDFを即時取込し要確認で一覧化 (Priority: P1)

施設からのメール添付PDFを受信すると、即時に注文レコードが生成され、一覧に「要確認」で出る。

**Why this priority**: 入力作業ゼロ化と遅延防止の根幹であり、全運用の入口となるため。

**Independent Test**: メールにPDFを添付して転送し、一覧に要確認として表示されるかを確認するだけで価値を提供できる。

**Acceptance Scenarios**:

1. **Given** メールが転送される, **When** 添付PDFが受信される, **Then** 施設×週の注文レコードが生成されPDFが保存される  
2. **Given** 抽出が走る, **When** 明細が生成される, **Then** 結果が一覧に要確認で表示される  
3. **Given** 施設名が確定できない, **When** 一覧に表示する, **Then** 「施設未確定」として選択待ち状態になる  
4. **Given** 同一施設×同一週のPDFが既にある, **When** 新しいPDFを受信する, **Then** 新しいPDFを採用し古い注文は出力対象外になる

---

### User Story 2 - PDF原本を見ながら修正し確定で出力更新 (Priority: P1)

運用者はPDFビューアを見ながら明細をインライン修正し、「確定」で保存・出力更新できる。

**Why this priority**: OCR誤りを運用で吸収し、出力の正確さを担保するため。

**Independent Test**: PDFを開いて明細を修正し、確定後に出力が更新されるかを確認すれば価値が得られる。

**Acceptance Scenarios**:

1. **Given** 明細を編集する, **When** 確定する, **Then** 修正値のみが正として保存される  
2. **Given** OCR値と修正値がある, **When** 出力を生成する, **Then** 修正値が採用されOCR値は出力に使われない  
3. **Given** 確定後, **When** 出力生成が走る, **Then** ラベルCSV・納品書Excel・総量CSVが自動更新される  
4. **Given** 週IDを変更する, **When** 変更後の週を保存する, **Then** 再計算・再出力が行われる

---

### User Story 3 - 週次メニューをアップロードし項目を確定 (Priority: P1)

管理者は週次メニューExcelをアップロードし、単位/量/温冷/時間帯/区分を行ごとに確定する。

**Why this priority**: 袋分けとラベル表記を安定させる前提データとなるため。

**Independent Test**: メニューをアップロードし設定値を保存、出力に反映されることを確認すれば単独で価値がある。

**Acceptance Scenarios**:

1. **Given** メニューExcelをアップロードする, **When** 週とメニュー一覧が生成される, **Then** 週に紐づくデータが保持される  
2. **Given** メニュー行を編集する, **When** 単位/量/温冷/時間帯/区分を設定する, **Then** 値が保存される  
3. **Given** 設定が保存されている, **When** 袋分けと出力を行う, **Then** 設定が反映された結果になる

---

### User Story 4 - 施設マスターでテンプレとルールを管理 (Priority: P2)

管理者は施設マスターでテンプレ・ルール・ラベル/納品設定を更新し、新規施設追加に対応できる。

**Why this priority**: コード改修なしで施設差分を吸収し、運用スピードを維持するため。

**Independent Test**: 新しい施設マスターを登録し、次回処理がマスター内容で実行されることを確認すれば価値がある。

**Acceptance Scenarios**:

1. **Given** 施設マスターに施設情報を追加する, **When** 保存する, **Then** 施設名とエリアが管理できる  
2. **Given** 施設マスターで抽出/袋分け/ラベル/納品書設定を更新する, **When** 次回処理を行う, **Then** 新設定が適用される  
3. **Given** 新施設を追加する, **When** コード変更なしで運用する, **Then** マスター設定のみで出力が生成できる

---

### Edge Cases

- 施設名抽出が低信頼/候補複数/0件の場合は運用者が施設を選択する
- OCR失敗時はリトライ（初期3回、設定可能）し、失敗時は手入力へ移行する
- 「未記入」セルは0扱いとし出力しない
- 変更欄の数値は差分ではなく変更後の数として採用する
- 1PDF複数ページは統合せず別施設として扱う運用で吸収する（MVP方針）
- 禁食・特記事項の自然言語混入は施設マスターポリシーに従い反映し、必要なら注文単位で上書きする

## OCR Strategy (MVP)

- 罫線検出で表のグリッド（列境界/行境界）を復元し、列境界はテンプレの列順で確定する
- OCRはページまたは表ROIに対して1回だけ実行し、単語/トークン座標をセルに割当する
- ヘッダ文字の認識に依存せず、グリッドから列割当を行う
- 結合セル/空欄は forward-fill（例: 日付、日付内の数量）
- 手書きが落ちたセルだけ局所OCRで補完し、OCR回数を最小化する
- グリッド復元に失敗した場合のみ旧方式（ヘッダ/数値クラスタ）へフォールバックする

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主要エンティティに「3文字程度の接頭語＋数値/週表現」で一意IDを付与する（例：FAC00001、WEK2025W14）。
- **FR-002**: 受信メールと添付PDFを保持し、保持期間は設定可能（初期1〜2ヶ月）とする。
- **FR-003**: 転送メール添付PDFは全て即時処理対象とし、処理タイムゾーンはJSTとする。
- **FR-004**: 同一施設×同一週の注文が複数届いた場合、新しいPDFを採用し古い注文は出力対象外とする。
- **FR-005**: 施設名はPDF指定領域から抽出し、確定できない場合は運用者が選択する。施設エイリアス辞書は持たない。
- **FR-006**: 週次メニューExcelをアップロードし、週に紐づけて保持できる。
- **FR-007**: メニュー行ごとに単位種別、1人前量、温冷、朝昼夕、メニュー区分を設定でき、設定は出力に反映される。
- **FR-008**: 週次メニューは原則全施設共通とし、施設別例外は置換方式で登録できる（MVPは置換のみ）。
- **FR-009**: OCRは日本語・手書き/印字混在・半角全角混在を許容し、罫線グリッド抽出＋セル割当を基本とする。リトライ回数は設定可能（初期3回）。
- **FR-010**: 未記入セルは0とみなし、数量0の行はラベル出力しない。
- **FR-011**: 運用者の修正値を正とし、変更欄がある場合は変更後の数を採用する（差分ではない）。
- **FR-012**: 袋分けルールは施設マスターのデータ定義で管理し、コード変更なしで更新可能とする。
- **FR-013**: 袋分けは「施設×日付×朝昼夕×メニュー×食種×エリア」単位で計算し、エリアがある場合はエリア別に分ける。
- **FR-014**: ラベルCSVは現行形式互換で出力し、施設マスターの設定に従い冷蔵/冷凍と賞味期限（冷凍=喫食日+3ヶ月、冷蔵=喫食日）を計算する。
- **FR-015**: ラベルCSV行には施設名、賞味期限、保存方法、食事区分（朝昼夕・エリア・メニュー区分・必要なら別袋）、温冷、商品名、内容量、内容詳細、所在地、製造者、注意文を含める。
- **FR-016**: 納品書は施設×日単位でExcel出力し、列構成は施設マスターのテンプレート/マッピング定義に従う。
- **FR-017**: 納品書テンプレートは将来のフォーマット変更に追随できるよう差し替え可能とする。
- **FR-018**: 製造側総量CSVは現行運用のCSV形式互換で出力する。
- **FR-019**: UIはPCブラウザのみ対応し、トップページで週別進捗（未着/要確認/確定/エラー）を施設別に一覧できる。フィルタ（未着/完了/エラー/文字列検索）を提供する。
- **FR-020**: PDFビューアでズーム可能にし、インライン編集は確定ボタンでのみ保存する。エラー時は次のアクションと該当修正画面へ誘導する。
- **FR-021**: ロールは管理者と運用者の2種とし、管理者はマスター更新・テンプレ更新・ユーザー管理・ログ閲覧を行い、運用者は注文確認/修正/確定/出力取得を行う。
- **FR-022**: 認証は管理者=Googleアカウント、運用者=ID/パスワードを基本とし、詳細は計画で確定する。
- **FR-023**: 修正作業・アップロード・設定変更はログ化し、保持期間は設定可能（初期1〜2ヶ月）。業務エラーは運用者へ、致命的エラーは管理者へ通知する。
- **FR-024**: 確定操作に連動してラベルCSV・納品書・総量CSVを自動更新する。
- **FR-025**: ダウンタイム発生後は未処理メールを再処理し追いつけること。
- **FR-026**: 1日最大100施設を想定した処理性能を満たし、手動介入なしで運用できる。
- **FR-027**: セキュリティは厳格に保ち、アクセス制御・暗号化・監査を計画に沿って具体化する（MVP方針を維持）。
- **FR-028**: In/outデータおよび操作は構造化ログでFAC/WEKなどのトレースIDとともに記録し、監査可能にする。

### Key Entities *(include if feature involves data)*

- **Facility**: 医療/介護施設。エリアを含む。
- **FacilityArea**: 施設内の階/ユニット/通所/職員などのエリア。
- **FacilityMasterConfig**: 施設マスター設定（FaxTemplate、PackagingPolicy、LabelProfile、InvoiceTemplate/ColumnMapping）。
- **WeeklyMenu**: 週に紐づくメニュー一覧。
- **MenuItem**: メニュー行（単位/1人前量/温冷/朝昼夕/区分を保持）。
- **OrderDocument**: 受信PDF。
- **Order**: 施設×週の注文。
- **OrderLine**: 日付×区分×メニュー×食種×エリア×数量の明細。
- **Bag**: 袋分け結果。
- **LabelRow**: ラベルCSV 1行。
- **DeliveryNote**: 納品書Excel。
- **ManufacturingAggregateRow**: 製造総量CSV 1行。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 95%の添付PDFが受信から2分以内に「要確認」一覧へ反映される。
- **SC-002**: 施設名未確定のケースで、運用者が選択して確定するまでの操作が3クリック以内で完了する。
- **SC-003**: 確定からラベルCSV/納品書/総量CSVが更新されるまでが2分以内で完了する。
- **SC-004**: 同一施設×同一週の重複PDF受信時に旧データが出力対象外になる事例が100%担保される。
- **SC-005**: 2時間のダウンタイム後でも、100施設/日規模で未処理メールを30分以内に再処理し平常状態に戻れる。

## Assumptions

- 既存運用のラベルCSV形式と文字コード（現行想定のCP932）を踏襲できることを前提とする。
- 管理者のGoogleアカウント連携と運用者のID/パスワード発行が可能なこと。
- 対象施設分の施設マスター情報（テンプレ・ラベル/納品設定）が初期投入されること。
- メール転送設定が既に行われ、添付PDFを受信できる前提であること。
